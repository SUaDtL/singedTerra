SEC-SEQUENCE

Delivery sequence and review size

Blocks
  • Establish the target architecture, protected-state baseline, content representation and release bar.
  • Implement shared presentation, game/application ownership, content authoring, platform services and reusable verification as coherent playable slices.
  • Integrate real consumers, migrate safely and remove superseded code; verify extension and player journeys.
  • Produce source-bound browser and Android development builds and record the remaining public-release gaps. Broad changes are acceptable; an unusable intermediate platform is not the sprint outcome.
SEC-BOUNDARIES

Compatibility and acceptance

Blocks

Sweeping architecture, module, content-pipeline and presentation changes are permitted when they serve an extensible releasable game. Preserve progression, retained run rules, player capabilities and safe saves; versioned formats may evolve with proven lossless migration. Keep Unity for the browser/Android roadmap, and keep separate TypeScript modes functioning. New mechanics, monetization, accounts or online services are not silently invented by architecture work.

References: SRC-RULES SRC-DIRECTION SRC-UNIFY SRC-RELEASE-OWNER SRC-PLATFORM

PR 543/544 were draft/open at the planning baseline and must be rechecked before implementation. Earlier funded-research, native, background, audio and endurance obligations remain distinct. Deliver the foundation as coherent reviewable changes from the verified base; opening a PR or producing a development build does not authorize merge, publication or store submission.

References: SRC-STACK
SEC-CHECKS

Verification policy

Blocks

Run relevant checks before and after each affected extraction, reusing valid evidence while inputs match. Source-bound baseline fixtures and behavior oracles remain independent; a common schema only proves contract shape. No suites or browser/native qualification were executed to author this plan. Commands marked proposed create focused new structural tests, not current passing evidence.

References: SRC-COMMANDS SRC-TOOLS

Owner-authorized consolidation may intentionally change UI or interaction behavior. Before implementation, record the target, benefit and shared owner; adjust affected assertions to that target and retain independent capability, accessibility, state-safety and negative checks. Cosmetic identity with the baseline is not the acceptance goal.

References: SRC-UNIFY
SEC-RELEASE

What this sprint delivers

Blocks

A playable, extensible Last Stand foundation with a unified experience, validated content growth, durable browser/Android platform support and a repeatable build path. The acceptance bar is the actual game and its extension/release workflow, not file size or duplication metrics. Full public release still depends on documented product and device qualification; unavailable native checks are reported as incomplete.
