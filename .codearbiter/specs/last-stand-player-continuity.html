Last Stand: player continuity and patched Unity

Protect and restore local campaign progress, make recovery and Help understandable, and qualify a matching Unity 6000.3.27f2 candidate.

SEC-TRANSACTION

Restore sequence and data boundary

Blocks

Read at most 128 KiB; validate a fixed ASCII version header and strictly decode the remaining confirmed-profile JSON bytes through the existing parser. This avoids a second JSON string envelope and retains existing JSON structure/string limits. Preview against an immutable capture of destination bytes/revision without reconciling research or mutating storage. Replacement is allowed only in the garage with no live Session.Model and no pending transaction. A safe Return to Garage action preserves the last confirmed checkpoint and explains rollback of partial-wave progress; it does not abandon the saved run. After Replace save confirmation, recheck the captured destination and exclusive ownership, preserve predecessor bytes through a separate allowlisted recovery-storage capability and confirm its readback, commit through the progression owner and confirm primary readback. If preparation fails, leave the original untouched. If the commit result is uncertain, retain recovery state and reconcile actual bytes before further action. Never automatically restore a backup over current or future-version data. Device preferences and arbitrary storage are excluded.

References: SRC-SAVE SRC-PLATFORM
SEC-TRANSPORT

Platform transport and lifecycle

Blocks

One domain codec and one restore coordinator feed capability-specific file adapters. WebGL uses a temporary gesture-bound file input and Blob download; Windows uses OS Open/Save dialogs; Android uses user-selected document URIs through a first-party Java bridge with bounded ContentResolver streams. No third-party file-picker dependency or broad storage permission. Correlate callbacks, reject late results, release resources, keep manual pause, and preserve all progress on cancellation or unavailable capabilities.

References: SRC-ANDROID-SAF SRC-PLATFORM
SEC-RELEASE

Qualification boundary

Blocks

This sprint owns continuity implementation and bounded patched-candidate verification. The existing Q-RECOVERY matrix remains the current external-acceptance owner. Physical Android lifecycle, hardware audio, real-duration farming/thermal evidence, owner comprehension/art acceptance, hosted checks, merge and deployment each retain their own actual status. No diagnostic export, final art choice or release/store submission is added.

SEC-SMARTS

SMARTS design rationale

Blocks

Recorded intent constrains this choice: local-only progression, shared authority and a releasable game. Real file transport is selected within the authorized sprint. Compare file transport with a clipboard-only alternative; no cloud/account alternative is in scope.

Recommendation strength: strong. The owner prioritizes a releasable game; durability and understandable player-controlled recovery outweigh fewer adapters. Non-SMARTS constraints: no paid package or service, one local profile, existing shared UI, bounded sprint.
