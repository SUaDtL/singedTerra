Sections

SEC-01

Save and failure contract

Blocks

Store one JSON object under singedTerra.lastStand.prototype.v1: version=1, nonnegative integral credits, permanentLevel 0..3, monotonic nextRunId, lastFinalizedRunId, and optional pendingDefeat containing runId, reward=1, elapsedTicks and kills. Reserve and persist a new run ID before Deploy. Capture ordinary defeat metrics before ReturnToInspection releases the model, and persist the pending reward before enabling Claim. Claim atomically clears pendingDefeat, adds one credit, and records the finalized run ID in one write. Purchase atomically subtracts its exact cost and increments the level in one write. Commit in-memory economic state only after setItem and exact readback succeed. Exact duplicate callbacks/claims do not award twice. A lost active run on reload is abandoned without reward; a saved pending defeat restores the claim flow. A missing record initializes zero state through a successful write; malformed, unsupported-version or inconsistent saved data is preserved and blocks economic transitions with an explanation and Retry. Storage failure preserves current committed state and pending operation; Retry reconciles a matching already-written candidate before retrying so a write followed by failed readback cannot duplicate rewards. Do not silently replace durable storage with memory or auto-reset corrupt data. No claim of crash-proof disk persistence or concurrent-tab atomicity.

SEC-02

Player flow and feedback

Blocks

Garage has fitting, permanent level, cannon damage and next benefit, saved-state text and Deploy. Battle shows hull, elapsed time, kills, current cannon damage, pause and mute. Ordinary defeat lets final recoil/impact effects settle for a short bounded transition, then presents time, kills, reward, balance and Claim and Continue. Workshop has one Cannon Attack card with current -> next damage, cost, balance, insufficient/capped/disabled states, purchase confirmation and Redeploy. Results/workshop replace nonessential battle and review controls; at 800x600 the primary action stays visible and reachable. No A/B selector, recoil-preview, orbit or part-debug controls in gameplay mode. Original procedural cannon, impact/destruction, defeat and purchase cues use bounded overlapping AudioSources, unlock from Deploy, stop while paused/hidden and obey a visible mute retained for the current session. No deferred audio burst on resume. Web title/loading identify Last Stand.

SEC-03

Verification boundaries

Blocks

Use focused actual C# compiler cases, one real Unity Editor lifecycle/combat/scene check, and one source-bound Web export plus a bounded real-pointer loop at normal speed. Browser proof includes same-origin reload, saved pending reward and post-purchase state, plus compact layout and audio/mute/pause inspection. Existing early-tick review smoke alone is insufficient for this loop. Do not claim numeric C# coverage: Unity/C# is unmentioned in the repository Testing profile and no configured numeric coverage runner exists. Preserve source and saved review/legacy scene hashes. Owner visual acceptance and live-player feedback remain explicitly pending.
