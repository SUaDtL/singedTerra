Last Stand Mechanics Shop — playable upgrade vertical

Earn Scrap in combat, buy temporary upgrades through the Field Console, invest defeat Salvage in permanent starting levels, and verify both loops in the delivered WebGL preview.

Intent

INTENT-01

Intent

CallerPlayers in the dedicated Unity Last Stand browser mode and the owner testing localhost.
OutcomeA player earns Scrap, buys meaningful temporary build upgrades during a run, then spends defeat Salvage on permanent starting levels; existing progress survives migration and the complete loop is previewable.
ProblemThe existing track math and between-run Cannon Attack upgrade do not provide a playable temporary shop, a run-earned currency or a coherent catalog with actual combat effects.

Decisions

DEC-001

Track accounting

Authorityinherited
ChoiceRetain the owner-selected accounting rule level=min(M,P+n), next temporary price C(n+1), per-track run purchase count and cap refusal. The actual M/P caps, currency, deployment snapshot and concrete prices are proposed separately in this specification.
RationaleOnly the generic arithmetic and same-instance/fresh-run rule are inherited from the approved pure foundation. Numeric catalog/economy choices require this specification approval.
Source refSRC-003
DEC-002

First complete catalog and caps

Authorityproposed
ChoiceSix tracks: Cannon Attack, Launcher Attack, Hull Capacity, Armor, Cannon Cycle and Field Repair. Total cap M=8 and permanent cap P=3 for all six. Attack/Defense/Utility each have two tracks. Launcher Attack requires the launcher fitting; Field Repair requires repair. Permanent investment is available for either compatible fitting and belongs to the track/compatible role, never an item instance.
RationaleCovers both current fittings and attack/defense/utility with one bounded catalog; equipment/Skills/R&D remain separate.
Source refSRC-002
DEC-003

Temporary economy

Authorityproposed
ChoiceStart every run with zero Scrap. Each actual foe death grants exactly 3 Scrap, regardless of weapon. A track next purchase costs 5*(n+1) Scrap, independent of P and other tracks. No refund, transfer or conversion into Salvage.
RationaleFirst purchase is reachable after two kills; simple integer prices expose run-only counting and remain easy to tune in the catalog.
Source refSRC-001
DEC-004

Permanent economy

Authorityproposed
ChoiceOrdinary defeat still grants one claimable Salvage exactly once. Every track permanent level costs P+1 Salvage (1,2,3), caps at P=3, and changes the next deployed run baseline. Permanent purchases are available only out of a run after pending rewards are claimed and local saving is ready.
RationalePreserves Cannon Attack and the existing reward contract while extending the same permanent progression to the six-track catalog.
Source refSRC-004
DEC-005

Effect timing

Authorityproposed
ChoiceApply purchases atomically at a reconciled current run boundary. Reconcile elapsed ticks using the old stats before the intent can change them; refuse while debt remains or the run ends. Future ticks use new stats. Recompute cannon due time from the last shot and new period, with earliest next tick and at most one shot per tick; no retroactive extra shots. Hull Capacity adds 15 current and maximum hull on a successful temporary purchase, capped at the new maximum and never reviving a terminal run.
RationaleImmediate useful effects must not rewrite hidden-tab history, create burst rewards or manufacture a new clock owner.
Source refSRC-004
DEC-006

Shop and pause

Authorityproposed
ChoiceOpening the in-battle Mechanics Shop does not pause combat. Explicit Pause remains accessible and stops time; purchases are allowed during explicit pause at its settled boundary. Closing the shop restores focus to its entry control. Death, exit or technical failure closes the temporary shop and invalidates its pending intents.
RationaleSupports idle play without surprising implicit pauses and allows considered purchasing through the existing Pause control.
Source refSRC-001
DEC-007

Persistence and migration

Authorityproposed
ChoiceUse the existing Last Stand storage key with a strict version-2 record containing the six permanent track levels. Migrate valid version-1 Cannon Attack into its matching track and initialize other permanent levels to zero; preserve wallet, next run id, finalized run id and pending defeat exactly. Preserve existing 2048-character bound and integer validation. Save failures retain a retryable candidate; changed/unsupported/malformed data blocks destructive actions and is not reset or overwritten.
RationaleExisting user progress and uncertain-write reconciliation are part of the vertical, not a disposable prototype save.
Source refSRC-004
DEC-008

Run continuity

Authorityproposed
ChoiceSame-instance pause, focus changes, hidden-tab callback throttling and shop close/reopen retain the active Scrap/n ledger. On defeat, exit, Limit or failure, invalidate purchases, account for all kills in the last admitted step, freeze one immutable earned/spent/final-Scrap result snapshot, then clear spendable Scrap and n. Result refreshes may read that non-spendable snapshot; closing the result, reload or next deployment discards it. New deployment starts with zero Scrap/n. Keep current 20 Hz, bounded catch-up, 3600-tick playable horizon and no reward for Limit/technical failure/unfinished exit. No closed-document accrual or automatic redeployment.
RationaleSeparates final accounting from teardown so conservation and temporary-state reset have distinct, testable observation boundaries; the existing clock, horizon and no-award behavior remain inherited runtime constraints.
Source refSRC-004
DEC-009

Visual and input system

Authorityproposed
ChoiceExtend the current worn brass/charcoal Field Console with category tabs and six live upgrade cards. Every visible card shows current effect, next effect, permanent P, run purchases n, total level/cap, price and a textual affordability/cap/fitting reason. Use distinct named Scrap/Salvage displays, live feedback, keyboard focus and touch targets; keep time, hull, Pause, Mute and Return reachable. Preserve the approved 14-CSS-pixel minimum for all player-facing shop/workshop text and 4.5:1 normal-text contrast in every layout/phase, including prices and refusal messages; compact layouts scroll/reflow rather than shrink text.
RationaleUses the supplied primary image and current live UI as one system; no static mockup control or whole-world art rewrite. This carries the existing approved Field Console readability contract into the new cards and workshop without a supersession.
Source refSRC-005
DEC-010

Proposed balance is a first slice

Authorityproposed
ChoiceThese catalog values and prices are a proposed playable baseline, not endgame tuning. Preserve the existing 180-second Limit with zero Salvage. Observe high-investment builds in validation and show the prototype limit honestly; changing the horizon/reward contract requires a later owner decision.
RationaleThe bounded encounter can limit a strong build; extending pacing and passive progression would widen this feature into a different game loop.

Problem and intended player outcome

Blocks

Blocks
