Last Stand game UI and background play — Field Console

Replace oversized prototype overlays with a coherent live Unity interface and continue the active idle run across focus loss and hidden-tab throttling, preserving combat/economy/saves, explicit Pause and manual Claim; deliver a source-bound localhost preview for owner review.

Intent

INTENT-01

Intent

CallerPlayers using the dedicated Last Stand browser mode; the owner previews it on localhost.
OutcomeA consistent Field Console interface makes the existing garage-to-defeat-to-upgrade loop legible, operable and visually coherent with its battlefield. An unpaused active run continues logically while the loaded page is unfocused or hidden and returns with current state rather than requiring Resume.
ProblemThe current Last Stand screen has oversized generic panels that obscure the tank and do not provide the readable hierarchy and compact battle interface needed for a polished first piece. The current focus/frame-gap suspension also prevents the loaded idle run from progressing when the player switches windows.

Decisions

DECISION-01

Selected interface

Authorityproposed
ChoiceA Field Console: graphite/olive panels, brass accents, ivory live text, distinct primary action, compact perimeter battle HUD.
RationaleThe user delegated choosing the best concept. A is the strongest match to the actual tank and improves hierarchy without excessive ornamental metal.
Source refSOURCE-01
DECISION-02

Presentation owner

Authorityproposed
ChoiceRetain the existing dedicated Unity Canvas; use live UI controls and responsive layout. Do not introduce a second HTML in-game HUD or new framework.
RationaleCurrent state and intents already live behind the Unity loop owner; all required values are exposed. This limits synchronization/focus risk and retains browser/mobile-project continuity.
Source refSOURCE-03
DECISION-03

Visual parameters

Authorityproposed
ChoiceUse HULL terminology and actual current/120 value, green hull fill with numeric status, amber primary actions,44 pixel minimum targets,14 pixel minimum text,4.5:1 normal text contrast and five listed viewport profiles.
RationaleGenerated ARMOR wording and missing timer/kills are corrected to the actual model. Numeric readability and geometry limits make polish reviewable while final owner visual acceptance remains explicit.
Source refSOURCE-03
DECISION-04

Dedicated Last Stand background policy

Authorityproposed
ChoiceUnpaused runs continue across window blur, hidden tabs and delayed callbacks while the same document remains loaded. Explicit Pause excludes elapsed paused time. Use the existing 0.05 second model step with at most 128 steps per callback and retain remaining debt up to the existing terminal horizon. Background and catch-up cues are silent; new eligible foreground cues resume after reconciliation. Claim remains manual; no automatic purchase/redeploy or closed-page progression.
RationaleThe user explicitly requested idle background play. Same-document elapsed reconciliation addresses actual browser throttling, with bounded CPU work and unchanged deterministic combat/economy. Background silence retains the current sound expectation and prevents an audible burst on return. Budget is a reversible implementation parameter selected for this draft.

SEC-02

Mechanical and adversarial review

Blocks

Negative-intent question: if every criterion passed and nothing else changed, what would still be broken? Original battlefield visual acceptance and balance remain separate; a purchase-audio or other full-loop failure still blocks overall readiness even after a UI preview. The added criteria explicitly cover focus/hidden timing, paused elapsed time, terminal settling/manual awards, no replay feedback and legacy/review isolation; there is no additional in-scope phase/action left uncited. Strongest failure case: merely enabling background updates still loses throttled elapsed time, while naive catch-up can replay sounds, include paused time or change shared review behavior. AC-09/10/11 require clock-partition equivalence, bounded retained debt, real focus/hidden observations, actual nonempty audio evidence and unaffected-profile tests. Browser suspension can defer execution; SEC-03 makes that limit explicit. Compact viewport/focus risk remains governed by AC-06/07. The generated concept omits time/kills and uses ARMOR; AC-02 corrects it. No accepted classic-client ADR changes. No new follow-up harvest residue is promoted.

SEC-03

Background continuation parameters and browser limits

Blocks

This amendment interprets the requested idle behavior as a current, already-deployed run continuing while its page remains loaded, including hidden/minimized tabs. It stops at the existing terminal outcome and awaits manual Claim. It adds no closed-page progress, automatic loop repetition or offline reward economy. Explicit Pause remains the player-controlled stop. Model clock and presentation/audio admission are separate responsibilities.

References: SCOPE-06 AC-09 AC-10 AC-11

Browsers may throttle or suspend callbacks; hidden frames and immediate hidden storage writes cannot be guaranteed. Account for elapsed active time when the same page next receives a callback, retaining bounded debt and suppressing old cues. A discarded or reloaded document follows existing unfinished-run/no-award behavior. The guarantee is coherent same-document logical continuation, not constant frame execution in a frozen tab.
